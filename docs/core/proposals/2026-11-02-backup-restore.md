# 一致备份、恢复演练和升级保护

> 来源：11-02 的外部审查（[报告](../../history/2026-11-audit/report.pdf)，括号里是报告的编号）。审查建议把这一项放在所有修复之前：后面的提交、题目版本、有效证据都要改表或加迁移，动之前要有一个确认能用的回退点。修复顺序见 [现在](../../now.md#修复顺序)。

## 问题

- 一门课的数据分在几处：学习库下的 `.learning/learning.db`（SQLite，WAL 模式）、课程文件夹（Markdown、作答照片和附件）、`library/` 下的原 PDF 和解析结果，以及 DSH 的会话记录和附件（DSH 的数据目录）。没有一个入口能把它们作为同一时刻的一份备份，也没有在别的目录里恢复出来验证过（M01）。
- 运行中直接复制 `learning.db` 不可靠：还在 WAL 文件里的写入会漏掉，复制出来的库和 Markdown 也可能不是同一时刻的。
- 迁移只按版本号往前跑：用旧代码打开已经被新代码升级过的库照常启动；迁移前不自动备份，迁移失败只能手工找回（M02）。

## 方案

实施进展：备份、校验恢复、运行互斥、迁移保护、完整学习流程恢复、真实 DSH 历史读取及 11 个持久化单元的旧库升级夹具已验证，当前能力见 [设计](../design.md#备份和恢复)。Windows 本机试用仍由用户执行。

1. **备份命令**（`pnpm backup <目标目录>`，DSH 停着时运行；运行中则先拒绝并说明）：
   - 数据库用 SQLite 的在线备份（`node:sqlite` 的 `backup()` 或 `VACUUM INTO`）导出一份完整的库，不复制 WAL；
   - 复制课程文件夹、`library/` 和 DSH 的会话目录；
   - 写一份清单：每个文件的路径、大小和 SHA-256，数据库里各单元的迁移版本，代码的提交号，备份时间。不复制 `.env`、`.credentials.yaml` 这类密钥文件，清单里写明没带。
2. **恢复命令**（`pnpm restore <备份目录> <新学习库目录>`）：只恢复到空目录，先按清单校验每个文件，再放回原位。不覆盖正在用的学习库；要换回去，由你改 `LEARNING_HOME` 指向新目录。
3. **恢复演练**写成自动测试：用合成课程（目标、讲义、作答、复盘、批注、侧边会话总结）备份，恢复到新目录后启动服务，逐项读回，掌握状态全部重算后和备份前一致。
4. **升级保护：**
   - 启动时数据库里某个单元的迁移版本比代码认识的新，拒绝启动并说明"学习库是新版本程序写的"；
   - 有待执行的迁移时，先在学习库旁边自动做一次数据库备份，再迁移；迁移失败时说明备份在哪；
   - 每个单元保留一份旧版本库的夹具（合成数据），测试从它升级到当前版本。
5. development.md 写备份、恢复和换学习库的操作；README 加一句给使用者的备份方法。

## 放弃的方案

- **只备份 Markdown：** 作答、判分、掌握状态、批注都在数据库里，Markdown 不够恢复一门课。
- **运行中热备份整套数据：** 文件和数据库之间没有统一的快照点，做出来的备份可能前后不一致；单用户本机停一下 DSH 的代价小。
- **把密钥一起备份：** 备份可能被拷到别处；密钥由你自己保管，恢复后在设置页重填。
- **自动定时备份：** 先把手动备份和恢复做对，要不要定时以后再说。

## 验收标准

1. 合成学习库备份后，恢复到新目录并在 3182 启动：课程、讲义、测试结果、复盘、批注、侧边会话历史都在，掌握状态重算结果和备份前一致。
2. 清单里任何一个文件被改动或缺失时，恢复在校验阶段拒绝，不写入目标目录。
3. DSH 运行中执行备份，命令拒绝并说明原因。
4. 用比代码新的数据库版本启动时拒绝启动；有待执行的迁移时先生成备份，模拟一次迁移失败后能从这份备份恢复。
5. 备份目录里没有密钥文件。
6. `pnpm typecheck`、`pnpm test`（含 `tests/flow.test.ts`）、`pnpm build` 通过。

## 风险

- DSH 的会话目录结构属于 DSH，版本升级可能改变；备份按整目录复制，不解析它的内容。
- Windows 上文件被占用时复制会失败：只在 Linux 上验过的部分要在你的 Windows 机器上再跑一次备份和恢复。
- 在真实学习库上第一次备份前要先问你（会读到真实教材和照片，但不发给任何服务）。
