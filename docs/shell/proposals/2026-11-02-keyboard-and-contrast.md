# 菜单和命令面板能用键盘、读屏跟得上，浅色小字够清楚

> 来源：11-02 的外部审查（[报告](../../history/2026-11-audit/report.pdf)，括号里是报告的编号）。修复顺序见 [现在](../../now.md#修复顺序)。这不是完整的无障碍认证，只修审查实测到的几处。

## 问题

- **菜单只有视觉高亮（FE-09）：** 共享菜单（`kit` 的 `ui.tsx`）用方向键移动时只改 `data-active` 样式，焦点不在菜单项上，也没有 `aria-activedescendant`，读屏不知道选到哪一项。
- **命令面板（Ctrl K）声明了模态，却不像模态（FE-09）：** 写了 `aria-modal`，但 Tab 能移出面板；焦点到了选项上再按 Esc 不关闭（Esc 只在输入框里处理）；关闭后焦点不回到原来的位置；输入框没有 `aria-activedescendant`。
- **侧栏宽度只能用鼠标拖（FE-09）：** 分隔条没有 `tabIndex`、键盘操作和 `aria-valuenow/min/max`。
- **最浅的文字颜色对比度不够（FE-10）：** `--la-text3` 在浅色主页面上 3.46:1、浅色外壳 3.22:1、深色主页面 4.25:1、深色浮层 3.88:1，低于普通文字 4.5:1 的要求；页码、出处路径、侧栏标题、资料信息都用它，而且是 12 像素小字。

## 方案

1. **菜单：** 打开时焦点进第一项，方向键移动真实焦点（roving tabindex），Home/End、首字母跳转，Esc 关闭并把焦点还给触发按钮；菜单项用 `role="menuitem"`。
2. **命令面板：** 焦点限制在面板内（Tab/Shift+Tab 循环），背景 `inert`；面板任意位置按 Esc 都关闭，关闭后焦点回到打开前的位置；输入框是 `combobox`，用 `aria-activedescendant` 指向当前选项，选项有稳定的 ID。
3. **分隔条：** `role="separator"`、可聚焦，左右方向键按步调宽度，带当前值和范围。
4. **颜色：** 调深（浅色）或调亮（深色）`--la-text3`，在所有常用底色上达到 4.5:1；纯装饰、禁用状态用另一个变量，不受这条限制。给设计变量加一个对比度检查的测试（读 `shell.css` 的两套颜色算对比度）。

## 放弃的方案

- **换一个现成的组件库：** 外壳和控件是我们自己设计的（AGENTS.md），只补缺的键盘和读屏行为。
- **把小字改大到 14 像素以上来避开要求：** 对比度的要求对大字才放宽到 3:1，小字改大会挤乱布局。

## 验收标准

1. 只用键盘：打开菜单、选项、关闭；Ctrl K 打开命令面板、搜索、选择、Esc 关闭，焦点回原处；Tab 不离开面板；调整侧栏宽度。
2. 至少用一种读屏（NVDA 或 VoiceOver，由你在自己的机器上试）核对：方向键移动时读出当前项，视觉高亮和读屏焦点一致。
3. 对比度测试通过：信息性小字在两套颜色的常用底色上都至少 4.5:1。
4. 按 `learning-ui-review` 在三种宽度、390 宽手机和深浅两色下截图核对；颜色调整是审美方向的事，由 Claude 定（10-05 的授权）。
5. `pnpm typecheck`、`pnpm test`、`pnpm build` 通过。

## 风险

- 文字颜色调深后，界面的层次会变弱；截图对比，必要时同时调整次要文字的用法。
