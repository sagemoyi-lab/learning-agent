# 手机上的布局

> 你 11-01 的要求（原话见 [throughts.md](../../throughts.md)）：给前端做移动端响应式适配。调研和现状见 [research.md §5](../research.md#5-手机上的布局11-01)。

## 问题

窗口窄于 600 像素（手机竖屏）时，外壳还按桌面排：图标栏占宽、标签栏挤成一团、状态栏文字重叠、右侧栏不满屏；手指选中讲义文字不出浮条；按钮和列表行太小，输入框聚焦时 iOS 会放大页面。页面内容本身大多已经能按宽度排好。

## 方案

只在窗口窄于 600 像素时换成手机布局（外壳按窗口宽度判断，和侧栏浮起的规则用同一个宽度来源）；600 像素以上的布局不变。

- **底部导航栏代替图标栏：** 课程切换、放得下的功能图标（按宽度算，390 像素放 4 个）、最后一个"更多"（放不下的功能、设置、外观）。每个按钮在图标下面写 2–4 字的名称：手机没有悬停，只有图标认不出来。角标照常显示，"更多"里有待办时"更多"带一个点。
- **顶部一行：** 标签栏收起，每个标签页面顶部那一行变成手机的标题栏：后退、前进、当前页面的名称，右边是搜索、提问和标签数按钮（Obsidian 手机版的做法）。点标签数列出所有标签（点了切换），下面是新标签页、刷新、固定、关闭、关闭其他。手机上不提供分屏。
- **侧栏和右侧栏：** 侧栏从左边浮出，最宽 360 像素，右边留一条点了收起；右侧栏（提问、出处）盖满主区，只留底部导航栏。点底部导航栏去别的功能时，两者都收起。
- **状态栏：** 不显示（阶段进度、待作答、下一步在课程进度页和角标上都有），只有推送断开时显示一行"正在重连"。
- **手指操作：**
  - 按钮 40 像素高，小按钮、图标按钮和列表行至少 36 像素；
  - 输入框 16 像素字；
  - 触屏上选中文字后（选区停下来约 0.4 秒）报告选区，讲义的"提问 / 批注"浮条放在选区下方，避开系统的复制菜单；
  - 触屏上不显示键盘快捷键提示。
- **顺带修的页面问题：** 首页"继续学习"卡片在窄宽度下把按钮换到下一行；主老师对话在窄宽度下收小边距；修好窄主区里"搜索""提问"按钮的宽度规则。

## 放弃的方案

- **底部栏横向滚动放全部图标：** 滚出去的功能看不到，也不知道还能滚。
- **左上角汉堡菜单收起图标栏：** 去任何功能都要多点一次；Obsidian 手机版也是用底部导航栏。
- **手机上保留标签栏：** 一个标签不到 100 像素看不出标题，而且顶部要占两行。
- **单独做手机版或 PWA：** 现在只在本机用，先让同一个前端在窄窗口里能用。
- **只用 CSS 媒体查询换布局：** 侧栏要不要浮起、点图标做什么由外壳的状态决定，宽度规则只放一处。

## 验收标准

1. 在 360、390、430 像素宽的触屏模拟下（浅色、深色）：页面不横向滚动；每个功能都能从底部导航栏或"更多"打开；角标看得到。
2. 标签数按钮能切换、新建、关闭标签；后退、前进可用。
3. 点"课程讲义"浮出目录，点一节后目录收起、打开讲义；"提问"盖满主区，点底部导航栏去别处时收起。
4. 讲义里用手指选中一句，选区下方出现"提问 / 批注"浮条。
5. 输入框字号 16 像素；按钮至少 36 像素高。
6. 1440、1024、760 宽度下的外壳和改前一样（"搜索"按钮规则的修正除外）。
7. 前端类型检查、`pnpm test`（含 `tests/flow.test.ts`）、`pnpm build` 通过。

## 风险

- 只在 headless Chromium 的触屏模拟里看过：真手机上的地址栏伸缩、软键盘盖住输入框、iPhone 底部横条的留白要你在真手机上试。
- DSH 只监听本机（127.0.0.1），手机要访问得把 DSH 开到局域网上，这超出"只在本机用"的范围，这次不做；可以用电脑浏览器的手机模拟或把窗口拉窄来试。
- 手机上没有分屏和标签拖动；窗口拉窄之前开着的分屏会挤在一起，用"只看这一栏"放大。
